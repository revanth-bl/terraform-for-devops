# 📦 Terraform State

## 📖 Introduction

**Terraform State** is Terraform's **source of truth** for the infrastructure it manages.

Whenever Terraform creates, updates, or deletes infrastructure, it records the current state in a file called:

```text
terraform.tfstate
```

This file maps your Terraform configuration to the real-world cloud resources, allowing Terraform to determine what changes are required during future operations.

Without the state file, Terraform would not know which resources it manages.

---

# Why Does Terraform Need State?

Imagine Terraform creates an EC2 instance.

```
Terraform Configuration

↓

Create EC2 Instance

↓

AWS
```

Later, you run:

```bash
terraform plan
```

Terraform must answer questions such as:

- Does the EC2 instance already exist?
- Has it changed?
- Should it be updated?
- Should it be replaced?

The **state file** provides these answers.

---

# What is Stored in the State File?

The state file typically contains:

- Resource IDs
- Resource names
- Resource attributes
- Dependencies
- Metadata
- Output values
- Provider information
- Sensitive values returned by some providers (when applicable)

Example:

```text
terraform.tfstate

↓

aws_instance.web

↓

Instance ID

↓

Public IP

↓

Availability Zone
```

---

# State File Location

By default, Terraform stores the state locally:

```text
terraform.tfstate
```

A backup is also created:

```text
terraform.tfstate.backup
```

For production environments, a **remote backend** is recommended instead of local state.

---

# How Terraform Uses State

Workflow:

```text
Terraform Configuration
           │
           ▼
Read State File
           │
           ▼
Compare With Cloud Infrastructure
           │
           ▼
Generate Execution Plan
           │
           ▼
Apply Changes
           │
           ▼
Update State File
```

---

# Example

Terraform configuration:

```hcl
resource "aws_instance" "web" {

  ami = "ami-123456789"

  instance_type = "t2.micro"

}
```

Run:

```bash
terraform apply
```

Terraform:

1. Creates the EC2 instance.
2. Stores its ID in `terraform.tfstate`.

Later:

```bash
terraform plan
```

Terraform compares:

```
Configuration

↓

State

↓

Actual AWS Infrastructure
```

Only the necessary changes are planned.

---

# State File Structure

A simplified example:

```json
{
  "resources": [
    {
      "type": "aws_instance",
      "name": "web"
    }
  ]
}
```

The real state file contains significantly more metadata and resource attributes.

> **Important:** Avoid manually editing the state file unless absolutely necessary.

# State Refresh

Terraform compares the recorded state with the actual infrastructure during planning and applying to detect changes.

To explicitly refresh the state in modern Terraform versions, use:

```bash
terraform apply -refresh-only
```

Or:

```bash
terraform plan -refresh-only
```

> **Note:** The older `terraform refresh` command is deprecated in recent Terraform versions.

# Local State vs Remote State

## Local State

```
terraform.tfstate

↓

Stored On Local Computer
```

Advantages:

- Simple
- Easy for learning

Disadvantages:

- No collaboration
- Easy to lose
- No built-in locking

---

## Remote State

```
Terraform

↓

Remote Backend

↓

Shared State
```

Advantages:

- Team collaboration
- State locking
- Versioning
- Encryption
- High availability

Examples:

- Amazon S3
- Azure Storage
- Google Cloud Storage
- Terraform Cloud
- HCP Terraform

---

---

# State File vs Configuration

| Configuration | State |
|--------------|-------|
| Desired infrastructure | Current managed infrastructure |
| Written by the user | Generated by Terraform |
| `.tf` files | `terraform.tfstate` |
| Can be edited | Should rarely be edited manually |

# Best Practices

- Use a remote backend for production.
- Enable state locking.
- Enable backend encryption and versioning.
- Never commit `terraform.tfstate` to Git.
- Back up state before making manual changes.
- Avoid editing the state file manually.

---

# Common Mistakes

❌ Deleting the state file accidentally.

❌ Committing the state file to version control.

❌ Editing the state file manually without understanding the consequences.

❌ Using local state for team environments.

❌ Ignoring state backups before performing state operations.

# Interview Questions

### What is Terraform State?

Terraform State is a file that records the infrastructure Terraform manages and maps the configuration to real cloud resources.

---

### What is the default Terraform state file?

```text
terraform.tfstate
```

---

### Why does Terraform need a state file?

Terraform uses the state file to determine the current infrastructure, compare it with the desired configuration, and generate an execution plan.

---

### Where should production state be stored?

In a secure remote backend such as:

- Amazon S3
- Azure Storage
- Google Cloud Storage
- Terraform Cloud
- HCP Terraform

---

### Should you edit the state file manually?

Generally, no. Manual edits should only be performed when absolutely necessary and with a proper backup.

---

### Is the state file sensitive?

Yes. It may contain infrastructure metadata and sensitive values returned by providers, so it should be protected.
